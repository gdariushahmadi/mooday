The directory is organized by purpose rather than code layering:
- `phase-1-audit/` is the canonical Phase 1 delivery contract: a top-level README enumerates nine screen areas (Shell, Discover, Search, Product, Sell, Checkout, Vault, Activity, Chat, Settings), each with Current state / Target / Acceptance criteria / Primary files, plus per-screen subfolders (`p1-01-shell`, `p1-02-discover`, …) containing bilingual screenshots and implementation notes. A `baseline/` folder holds current-state reference captures at `393 × 852`.
- `plans/` holds time-stamped feature launch plans and a session handoff ledger (`HANDOFF.md`, `IMPLEMENTATION.md`) tracking verified DoD, operational DoD, code artifacts, known remaining work, and risks for the next session.
- Root-level markdown files are domain-area specs and progress trackers grouped by user area (`group-*`, `progress-u*`, `checkout-flow.md`, `search-filters.md`, `user-scenarios.md`, etc.) and by phase (`phase-2-backend.md`, `phase-3-marketplace.md`).
- Operational runbooks live at the root (`DEPLOY.md`, `DEPLOYMENT_CPANEL.md`, `SMOKE_TESTS.md`, `EXTERNAL_SETUP_TODO.md`, `STATUS.md`, `app-lock.md`).
Dependency direction is one-way: these documents reference source paths under `src/` and Supabase migrations but contain no executable code; they serve as the authoritative spec against which code changes are reviewed.
