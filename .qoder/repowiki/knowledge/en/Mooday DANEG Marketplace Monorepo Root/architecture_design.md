The repository is a single Next.js application (output: standalone) whose `next.config.ts` centralises security headers, CSP, PWA service-worker manifest routing, and Sentry instrumentation; all runtime configuration flows through environment variables (`NEXT_PUBLIC_SUPABASE_URL`, `SENTRY_*`). The frontend_app consumes the backend_client abstraction to talk to Supabase, which in turn executes the migrations defined in database_schema. Scripts_and_deploy orchestrate the full lifecycle — building the standalone bundle, seeding demo data via the backend_client seeders, applying Supabase migrations, and running phase-gated smoke/E2E tests against a live instance. Public_assets are served under `/public` and consumed by both the frontend and the Playwright E2E suite in tests. Docs_and_plans define acceptance criteria that the test suite validates, forming a closed loop from spec → code → migration → deploy → verify.
