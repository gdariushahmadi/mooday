Two cooperating sub-trees under this scope:
- `scripts/` contains Node/MJS utilities invoked via npm scripts in `.deploy/package.json`. They are grouped by purpose: build tooling (`build-standalone.sh`, `generate-icons.js`), data ops (`seed-demo-catalog.mjs`, `apply-migrations.mjs`), and smoke tests named per release phase (`phase2-auth-smoke.mjs`, `phase2-smoke-supabase.mjs`, `u3-u8-smoke.mjs`, `phase4-*-smoke.mjs`). Each smoke script loads env via `@next/env`, connects to Supabase (or Mailpit for OTP polling), performs an end-to-end scenario, asserts with a local `assert`, and cleans up its test artifacts.
- `.deploy/` is the Next.js standalone output directory copied by `build-standalone.sh`: it holds the generated `server.js`, a minimal `package.json` pinning Node ≥20.9.0, the `public/` assets, and the `.next/` runtime tree. The bundled `server.js` sets `NODE_ENV=production`, chdirs into itself, reads `PORT`/`HOSTNAME`/`KEEP_ALIVE_TIMEOUT`, and starts Next via `startServer({ isDev: false })` so Passenger or any process manager can host it.
Dependency direction is one-way: scripts depend on the built app's environment and Supabase; the deploy bundle depends only on the Node runtime and the copied `.next/standalone` artifacts. There is no shared library between scripts — each is self-contained and invoked directly from npm scripts.
